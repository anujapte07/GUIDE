## How the LLM was provided
The ROME code is the course's own. With a key in the environment (`CLAUDE_API_KEY`, or `OPENAI_API_KEY` + `MODEL=ChatGPT`)
the notebook runs **live**, as the original does, and saves new responses to `llm_responses_live/`.
**The submitted outputs were produced in replay mode** (no key set). Each LLM response was written by Claude (`claude-opus-5-5`)
for the exact prompt the pipeline built, and is stored in `llm_responses/<section>/NNN.json`. The machine I used had no API access.
All parsing, file writing, iverilog/vvp simulation, Yosys PPA estimation and Covered runs are real and re-run every time.

**One recorded response has a deliberately seeded fault.** The notebook prints a NOTE when it serves it, and the JSON has a `seeded_fault` field:
`llm_responses/part2_adder_hier/003.json` (first `adder8`) flags negative overflow only. The baseline TB can't see this bug. It exercises Step 4 of the assignment:
the coverage-guided TB exposes the bug, the TB is frozen, and ROME repairs the RTL.

## Reproduce
Linux, Colab or WSL. Covered does not run on native Windows.
```bash
sudo apt-get install -y iverilog covered      # notebook does this if missing
pip install yowasp-yosys                      # recent Yosys for the PPA loop (notebook does this if missing)
jupyter nbconvert --to notebook --execute --inplace rome_submission.ipynb

# final check by hand
iverilog -g2001 -o adder8_final.vvp part3_coverage/final_rtl/{half_adder,full_adder,adder4,adder8}.v part3_coverage/tb_final.v
vvp adder8_final.vvp            # tests run: 19, mismatches: 0 / passed!
# any coverage run:  cd part3_coverage/cov_02_rtl_repair_1 && sh commands.sh
```
This folder contains no API keys or credentials. The last notebook cell scans for them.
